# 04: Restore tool names only where a response names a tool

**What to build:** oc-auth sends tools to Anthropic under tool aliases and puts
the OpenCode names back in each response. Today it rewrites every JSON field
named `name` or `tool_name` whose value is a tool alias, wherever the field
appears, including inside a tool call's input. When a JSON response carries such
a field in a tool input, OpenCode runs the tool with an input the model didn't
send. Restore names only in the fields where Anthropic's message format names a
tool, in JSON responses and in streamed events. The review reproduced this with
a JSON response. Streamed tool inputs arrive as escaped JSON text, and the
review didn't show them to be affected.

**Category:** bug

**Priority:** P2 (normal)

**Where:** `packages/oc-auth/src/tool-aliases.ts` and
`packages/oc-auth/src/response-restoration.ts`.

**Blocked by:** None (can start immediately)

**Coordinate with:** 05, which changes where restoration gets its aliases, not
which response fields it changes.

**Status:** ready-for-agent

- [ ] In a JSON response, only fields that name a tool, such as a tool-use
      block's name, are restored. Tool inputs, text, and every other field stay
      semantically unchanged. JSON whitespace and object-key formatting need not
      be preserved when a recognized tool-name field is rewritten.
- [ ] In a streamed response, only tool-name fields in events are restored, and
      each complete event passes on without waiting for later events or the end
      of the response. Decoded tool-input delta strings retain their exact
      content; only their enclosing JSON's formatting may change.
- [ ] Unknown fields within recognized messages or events retain their values.
      Unknown event types, malformed JSON bodies or event payloads, and bodies
      that aren't text pass through without rewriting. A malformed later event
      does not require buffering or undoing earlier events.
- [ ] Regression tests cover tool inputs with `name` and `tool_name` fields
      whose values are tool aliases, in JSON and streamed responses, alongside
      actual tool-name restoration. They also cover unknown events and fields,
      malformed payloads, and event boundaries split across input chunks.

### Triage Notes

**Verification:** Confirmed by inspection. Restoration matches
`"(name|tool_name)": "mcp_…"` anywhere in the text, over whole JSON bodies and
whole SSE chunks, so a tool input carrying such a field is rewritten. Streamed
`partial_json` text is escaped and is not matched, as the ticket says.

**Amendments:**

- Several existing tests pin the old rewrite-anywhere behavior with response
  shapes Anthropic doesn't send: a `{"type":"tool_use","name":…}` event, a
  top-level `{"name":…}` body, a name inside a text block, the shared
  `ALIASED_SSE` fixture, and the raw-text tests of the alias helper. These
  fixtures may change to real Anthropic message and event shapes; their intent
  (actual tool names are restored) must stay covered.
- Restore exactly these tool-name fields, mirroring what the request side
  aliases: a `tool_use` block's `name` (in a JSON message's `content` and in
  `content_block_start.content_block`, including inside `message_start`), and
  `tool_reference.tool_name` wherever tool-search results carry it. Server tool
  blocks (`server_tool_use`, `mcp_tool_use`) are not aliased by oc-auth and stay
  unchanged.

**Sequencing:** 05 adds tests around the same restoration fixtures; land one
before starting the other.
