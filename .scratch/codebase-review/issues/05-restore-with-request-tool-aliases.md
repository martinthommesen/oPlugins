# 05: Restore each response with its own request's tool aliases

**What to build:** oc-auth keeps a record of each request it rewrites, but it
restores tool names in the response from a separate cache of tool aliases per
session and request kind. That cache holds 512 entries. Once enough other
sessions are active, a session's entry is dropped. A response to a request
oc-auth rewrote, and still has a record of, then reaches OpenCode with tool
aliases that match no OpenCode tool. Restore each response with the tool aliases
its own request carried, and use the session cache only when the host hands back
a different request than the one oc-auth produced. The review reproduced this by
filling the cache with 512 other entries before the response arrived.

**Category:** bug

**Priority:** P2 (normal)

**Where:** `packages/oc-auth/src/session-hooks.ts`,
`packages/oc-auth/src/request-states.ts`, and
`packages/oc-auth/src/session-aliases.ts`.

**Blocked by:** None (can start immediately)

**Coordinate with:** 04, which restricts restoration to actual tool-name fields.

**Status:** ready-for-agent

- [ ] A response to a request oc-auth rewrote restores tool names with that
      request's aliases, even after the session's cache entry was dropped or
      replaced.
- [ ] When the response belongs to a request oc-auth has no record of,
      restoration still uses the session cache, as today.
- [ ] A request that oc-auth rewrites more than once keeps every alias it was
      sent with.
- [ ] Regression tests cover the dropped cache entry and the fallback to the
      session cache. They also rewrite the same request more than once and
      verify that aliases from its earlier rewrite still restore after the cache
      is dropped or replaced.

### Triage Notes

**Verification:** Confirmed by inspection. The per-request record holds only the
credential and request snapshot; aliases go only into the 512-entry session
cache, which evicts the oldest entry, and the response hook restores from that
cache even when it found the request's own record. The cache's own comment
already describes it as a fallback, which the code doesn't do.

**Amendments:**

- On a second rewrite of the same request the body already carries `mcp_` names,
  so the alias map computed from it is empty. The rewrite must inherit the
  aliases recorded for the incoming request.
- A response replayed by unauthorized recovery is restored with the original
  request's aliases.
- Also relevant: the outbound-request code that produces each request's aliases.

**Sequencing:** shares restoration test fixtures with 04.
