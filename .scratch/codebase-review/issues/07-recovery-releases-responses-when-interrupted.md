# 07: Unauthorized recovery releases its responses when interrupted

**What to build:** Unauthorized recovery keeps the original 401 response and
every response it opens while it adopts or refreshes the credential. It releases
the ones it doesn't return only after it finishes. If recovery is interrupted
partway, for example while it waits for a second refresh after adopted
credentials were also rejected, those responses are never released, and their
connections stay open until something else reclaims them. Release every response
recovery opened, except the one it returns, however recovery ends. The review
reproduced this: interrupting recovery during the second refresh left both
responses unreleased.

**Category:** bug

**Priority:** P2 (normal)

**Where:** `packages/oc-auth/src/unauthorized-recovery.ts` and
`packages/oc-auth/src/plugin-recovery-failures.test.ts`.

**Blocked by:** None (can start immediately)

**Coordinate with:** 06 for cancellation and 18 for failure reporting.

**Status:** ready-for-agent

- [ ] When recovery is interrupted without returning a response, the original
      401 and every response recovery opened are released.
- [ ] When a recovery failure falls back to the original 401, that response is
      returned unread and usable; only the other responses are released.
- [ ] A successful recovery returns its response unchanged and still streaming,
      and releases the rest. Any other response returned by recovery, including
      a retained 401, is likewise not cancelled by cleanup.
- [ ] A regression test interrupts recovery while it waits for the second
      refresh and checks that both responses were released.
- [ ] Regression tests also cover failure falling back to the original 401 and
      successful recovery. They verify both release of discarded bodies and
      continued readability of the returned body.
