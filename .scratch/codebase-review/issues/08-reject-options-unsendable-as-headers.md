# 08: Reject options that can't be sent as headers

**What to build:** The `userAgent`, `cliVersion`, and `entrypoint` options go
into request headers, and `betaFlags` goes into the `anthropic-beta` header.
Option checks replace control characters, but they accept characters a header
can't hold, such as non-Latin letters in `userAgent`, and line breaks in
`betaFlags`. With such a value, the plugin starts, then fails to build the
headers of every Anthropic request. Make every value that passes the checks
sendable, and make an unusable value stop the plugin from starting with the
usual options error. The review reproduced this with a non-Latin `userAgent` and
a `betaFlags` value with a line break.

**Category:** bug

**Priority:** P2 (normal)

**Where:** `packages/oc-auth/src/plugin-options.ts`,
`packages/oc-auth/src/claude-headers.ts`, and
`packages/oc-auth/src/model-config.ts`.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] A `userAgent`, `cliVersion`, `entrypoint`, or `betaFlags` value that still
      can't appear in its request header after the existing normalization stops
      the plugin from starting. The error names the option and doesn't quote the
      value.
- [ ] No value accepted at startup makes building request headers fail.
- [ ] Valid values, including ones whose control characters oc-auth already
      replaces, keep working as today. Existing beta-flag splitting, trimming,
      and omission of empty entries are preserved; validation checks the
      resulting header rather than rejecting raw whitespace that is already
      removed.
- [ ] Regression tests pass invalid options through plugin startup, not only
      directly to `Headers`. They cover non-header characters in each option,
      embedded line breaks that survive beta normalization, preserved
      header-text cleanup and beta trimming, and successful header construction
      for accepted boundary values.
- [ ] The README says which characters each of these options accepts and how its
      value is normalized before validation.

### Triage Notes

**Verification:** Confirmed by inspection, plus a Node 24 check: `Headers`
rejects `"клиент"` and U+2028 ("Cannot convert argument to a ByteString") and
`"a\nb"` ("invalid header value"), and accepts `"café"`. Option checks only
replace control characters; beta-flag trimming keeps inner line breaks.

**Amendments:**

- Accepted characters follow the Fetch header-value rules (Latin-1 bytes,
  including U+00A0–U+00FF). The implementer may restrict this further but must
  document the choice in the README.
- `cliVersion` and `entrypoint` reach a header only through the default user
  agent; validate each on its own so the error names the option that's wrong.
- The options error already names the option without quoting the value.
