# 09: Keep the active credential in step with the host's selection

**What to build:** oc-auth follows the host's Anthropic connection through its
credential-switch events, and subscribes again a second after the event stream
ends or fails. Two cases leave the active credential on the wrong Claude Code
account:

1. The user switches accounts while the event stream is down. oc-auth misses the
   switch and keeps the previous account's credential until the next switch. The
   review reproduced this.
2. Looking up the new account fails with an unexpected error, which is how the
   host's lookup of the active connection reports problems. oc-auth keeps the
   previous account's credential, and logs the error in a debug record as a
   failed model reload. The review found this by reading the code and the host's
   types. It wasn't reproduced.

Make the active credential match the host's selection after every reconnect, and
never leave the previous account's credential active after a failed switch.

**Category:** bug

**Priority:** P1 (urgent)

**Where:** `packages/oc-auth/src/credential-switches.ts` and
`packages/oc-auth/src/plugin-switches.test.ts`.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] After the event stream reconnects, the active credential matches the
      host's current Anthropic connection, even when the user switched accounts
      while the stream was down.
- [ ] Reconciliation and subscription are ordered so a switch during reconnect
      is not missed. A stale reconciliation result does not overwrite a newer
      selection, and the same protection applies at startup.
- [ ] A switch whose lookup fails, with a failure or an unexpected error, leaves
      no active credential. The warning names the credential lookup, not the
      model reload.
- [ ] A failed model reload is still reported as one.
- [ ] The existing behavior for a request racing an unresolved switch remains:
      it may use the previously active credential until the lookup finishes, but
      a failed lookup must then clear that credential.
- [ ] Unloading the plugin still ends its event subscription.
- [ ] Regression tests cover a switch while the stream is down and a lookup that
      fails with an unexpected error. They also exercise a switch in the
      reconciliation/subscription window and verify that the latest selection
      wins.

### Triage Notes

**Verification:** Confirmed by inspection. Resubscribing never re-reads the
active connection; startup reads it before subscribing, leaving a window. The
active credential is set unconditionally, so a slow lookup can overwrite a newer
selection. The host types `connection.active` with no error channel, so its
problems arrive as defects, which the lookup's failure handling and
`Effect.ignore` don't catch; the switch handler's defect catch then logs
`model_reload_failed` and keeps the old credential.

**Amendments:**

- **Extra finding:** at startup, the same defect has no handler and fails the
  whole plugin. A failed startup lookup must leave no active credential and let
  the plugin start, with the warning.
- If the credential-lookup warning is a new event rather than the existing
  `credential_reload_failed`, add it to the README's log table.
- The connection test fake needs a way to make `active` fail with a defect.
