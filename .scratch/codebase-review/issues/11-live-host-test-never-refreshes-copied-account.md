# 11: Live host test never refreshes a copied Claude Code account

**What to build:** Without `--offline`, oc-auth's host test copies the first
Claude Code account it finds, refresh token included, into a credentials file in
its sandbox. Its comments say the copied token is never refreshed, but the test
checks only that the token doesn't expire within five minutes. If Anthropic
rejects the access token, unauthorized recovery refreshes it and writes the
rotated tokens to the sandbox, which the test then deletes. The account's own
credential store can then hold a refresh token that no longer works, which signs
Claude Code out. The review found this by reading the code. It didn't run the
live test. Make a copied-account run unable to spend that account's refresh
token; refresh testing must use an explicitly supplied disposable account.

The unsafe mode is the live `pnpm run test:headless` command. The default
`pnpm run test:host` command already supplies `--offline` and does not read real
credentials.

**Priority:** P1 (urgent)

**Where:** `packages/oc-auth/scripts/headless-credentials.ts`,
`packages/oc-auth/scripts/test-host.ts`, and `packages/oc-auth/package.json`.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] A live run with a copied account can't refresh: either the copy can't be

- [ ] If copied-account mode is retained, a run that would need a refresh fails

- [ ] A regression test uses synthetic credentials and a fake token endpoint. If

      If the mode is removed, the test proves a live run without a disposable
      directory stops before reading an account. No regression test uses real
      credentials or calls Anthropic.

### Triage Notes

**Verification:** Confirmed by inspection. The live run copies the first
account, refresh token included, into the sandbox, checks only that the access
token is valid for five more minutes, and marks no refresh as expected, so
write-back checks don't run. A 401 sends the copied refresh token to the real
token endpoint and writes the result into the sandbox, which is then deleted.

**Amendments:**

- There is a second refresh path: the host's own refresh callback registered for
  the Claude Code method. Whatever makes the copy unable to refresh must cover
  both paths.
- Recommended choice: keep copied-account mode but make the copy unable to
  refresh, since the README advertises the workflow. Removing the mode remains
  acceptable under the criteria.
- The package's Vitest config includes only `src/`, and `../` imports are
  banned, so the regression test needs either the logic moved into `src/` or the
  test config extended.
