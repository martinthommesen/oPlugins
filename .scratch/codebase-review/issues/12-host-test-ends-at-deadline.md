# 12: Host test always ends at its deadline

**What to build:** The host test gives each command's exit code 180 seconds,
then calls `kill` without a force-kill grace period. The installed process
library bounds its process-group polling but subsequently awaits the leader's
exit signal, so a leader that ignores termination can still hold the caller.
Output collection has no deadline either: even a parent that exits promptly can
leave a descendant holding stdout or stderr open. These paths leave the test
hanging instead of reporting its timeout, which can stall CI until the job's own
time limit. The review found this by reading the code and the installed process
library. It wasn't reproduced. Bound the whole command operation, including
termination and output collection, and report a timeout with the output
collected so far.

**Category:** bug

**Priority:** P2 (normal)

**Where:** `libs/host-test/src/command.ts` and
`libs/host-test/src/command.test.ts`.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] A command that ignores the termination signal is force-killed after a
      short grace period.
- [ ] The deadline covers waiting for the process and collecting its output,
      even if the parent exits before the deadline while a descendant keeps an
      output stream open. Document the bounded cleanup allowance after the
      180-second deadline.
- [ ] A failed termination attempt cannot start an unbounded wait or hide the
      timeout. Report the termination failure alongside the timeout without
      claiming that a process was killed when that could not be confirmed.
- [ ] The test then fails with its timeout message and the output collected so
      far.
- [ ] Unit tests use fake processes and controlled time to cover ignored
      termination, a parent that exits while an output stream stays open, and a
      failed kill. They verify the elapsed bound and preservation of partial
      stdout and stderr.

### Triage Notes

**Verification:** Confirmed by inspection, against
`@effect/platform-node-shared` 4.0.1. The timeout covers only the exit code;
`kill` has no force-kill option, and the library then awaits the leader's exit
signal with no bound. The scope's release runs the same unbounded termination,
so wrapping the whole run in a timeout doesn't help; the command needs
`forceKillAfter`. A parent that exits 0 leaves descendants alive, and output
collection has no deadline. A failed kill fails the operation and loses the
timeout message and output.

**Amendments:**

- Also covered: a leader killed by a signal before the deadline fails the exit
  code with a platform error, which loses the output too.
- The command runner is shared by every plugin's host test (install, sandbox,
  checks, and oc-auth's headless checks).
- Document the cleanup allowance in the host-test library's README.
- The library's grace period runs on the real clock, so unit tests need a fake
  `ChildProcessSpawner` rather than real processes. oc-auth's Keychain runner
  already uses the force-kill pattern.
