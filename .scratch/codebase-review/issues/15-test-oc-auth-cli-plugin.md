# 15: Test oc-auth's CLI plugin

**What to build:** oc-auth's CLI plugin adds a Cache section to the session
sidebar and a `/cache` command that shows prompt cache stats. Tests cover the
stats calculations, but nothing tests the CLI plugin itself, and the build
checks only that its file exists. A command that's no longer registered, a
report for the wrong session, or a sidebar section that never appears would go
unnoticed. Add tests for the CLI plugin's behavior.

**Category:** enhancement

**Priority:** P2 (normal)

**Where:** `packages/oc-auth/src/tui.ts` and
`packages/oc-auth/src/cache-stats.test.ts`.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] Tests check that setup registers `/cache` in the command palette and as a
      slash command.
- [ ] Running `/cache` outside a session shows the warning toast. Inside a
      session, it shows the report for that session.
- [ ] The sidebar's Cache section appears once the session has used a prompt,
      shows the last request's hit rate when there is one, and follows the
      session the sidebar shows.
- [ ] Setup appends the section to `sidebar.content`. The test exercises the
      registered renderer, rather than only inspecting its registration metadata
      or testing the stats helpers.
- [ ] With the sidebar mounted, changing its session and updating that session's
      token/message data update the rendered section. A session without prompt
      tokens hides it; switching to one with prompt tokens shows the correct
      values. Changing the current route also changes which session `/cache`
      reports.
- [ ] The tests use fake CLI host APIs, with no module mocking.

### Triage Notes

**Verification:** Confirmed by inspection. Nothing imports the CLI plugin in
tests, and `verify:dist` only checks that its file exists.

**Caveat:** the command criteria can follow oc-browser's CLI plugin tests (fake
`keymap.layer` and toast, no module mocking). The sidebar criteria need the real
renderer:

- OpenTUI's element creation fails without a renderer context; its test renderer
  needs `node:ffi`, available in Node 26.1+ with `--experimental-ffi`. The
  repository pins Node 26.
- Under Vitest's Node environment, bare `solid-js` resolves to Solid's
  non-reactive server build, while `@opentui/solid` imports the browser build
  directly. oc-auth's Vitest config must resolve both to the same reactive
  build.

Both are per-package test-config changes. If running tests with
`--experimental-ffi` is not acceptable in CI, stop and move this ticket to
ready-for-human; the command criteria can then land on their own.

**Amendment:** put the tests in a new CLI-plugin test file rather than the cache
stats tests.
