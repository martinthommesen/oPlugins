# 16: Report failed credential-file cleanup, with tests that reach it

**What to build:** To write refreshed tokens back to a credentials file, oc-auth
writes them to a private temp file, renames it over the credentials file, syncs
the directory, and later sweeps up stale temp files. Each cleanup and durability
step ignores every failure. A temp file holding tokens that can't be deleted, a
failed directory sync, and a failed sweep all go unreported, though only
"unsupported" and "already gone" are expected. Also, the test meant to show that
a failed rename leaves no temp file fails earlier, while reading the credentials
file, so it never creates a temp file or attempts the rename. The review found
the ignored failures by reading the code and confirmed the test's gap. Report
these failures, and make the tests reach them.

**Category:** enhancement

**Priority:** P2 (normal)

**Where:** `packages/oc-auth/src/claude-code-file-store.ts` and
`packages/oc-auth/src/claude-code-file-temps.test.ts`.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] A temp file holding tokens that can't be deleted is reported: a warning
      with metadata only, and the error in a debug record.
- [ ] A failed directory sync or stale-temp sweep is reported the same way. A
      platform that doesn't support directory sync, and a file that's already
      gone, stay silent.
- [ ] None of these failures turns a write that landed into a failed write-back,
      or causes another refresh.
- [ ] The rename-failure test keeps a readable credentials file, makes the
      rename itself fail, and checks that the temp file is gone and the
      credentials file is unchanged.
- [ ] New tests cover a temp file that can't be deleted and a failed directory
      sync. They also cover a failed stale-temp directory scan and a failed
      per-file sweep operation, checking the warning and debug fields.
- [ ] Regression tests distinguish the expected missing-file and unsupported
      directory-sync cases from real failures. A sweep failure on one stale file
      does not prevent attempts to clean up the others, and tests confirm a
      landed write is still reported as successful.

### Triage Notes

**Verification:** Confirmed by inspection. Temp-file removal, directory sync,
and the stale-temp sweep all ignore failures, deliberately per their comments.
The rename-failure test puts a directory at the credentials path, so reading
fails first and the test never creates a temp file or attempts the rename.

**Amendments:**

- A landed write staying successful, one stale file's failure not stopping the
  others, and no extra refresh already hold today; they need regression tests.
- The implementer defines and documents which directory-sync errors count as
  "unsupported" (for example per-platform error codes). "Already gone" includes
  the not-found error from removing the temp file after a successful rename.
- Warnings must not include the config directory; it goes only in debug records.
- Add the new warnings to the oc-auth README's log table.
- A rename can't be made to fail while the read still succeeds using
  permissions, so tests need a `FileSystem` layer that fails selected operations
  by path.
