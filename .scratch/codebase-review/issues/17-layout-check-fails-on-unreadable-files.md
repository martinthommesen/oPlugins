# 17: Layout check fails when it can't read the repository

**What to build:** The layout check reads every plugin, library, and tool file
and checks it against the repository's layout rules. It treats a directory it
can't read as empty and a file it can't read as absent, so it can pass without
checking files it should have checked, or report a required file as missing
instead of unreadable. Unexpected failures also exit with an error status and no
explanation, because error reporting is off for the whole run. The review found
this by reading the code. It wasn't reproduced. Make the check fail, naming the
path and the reason, when it can't read what it should inspect, and print the
cause of any unexpected failure.

The current traversal also attempts to read ordinary file entries as
directories, using the same fallback to continue. Distinguish files from
directories rather than turning every failed directory read into an error.

**Category:** bug

**Priority:** P2 (normal)

**Where:** `tools/read-snapshot.ts` and `tools/check-layout.ts`.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] A directory or file the check should inspect that can't be read fails the
      check, and the message names the path and the reason.
- [ ] Files that are legitimately absent keep their current handling.
- [ ] Ordinary files are read as files and do not fail because they cannot be
      traversed as directories. Missing optional files remain distinct from
      existing but unreadable files or directories; permission and I/O failures
      are not treated as absence.
- [ ] An unexpected failure prints its cause, and layout problems still print
      once, as today.
- [ ] Tests cover an unreadable file, an unreadable directory, ordinary file
      traversal, legitimately missing files, and an unexpected failure. The
      check still passes on the current repository.

### Triage Notes

**Verification:** Confirmed by inspection. A failed directory read becomes an
empty list; a failed file read becomes absent, which the layout rules then
report as missing. Top-level files are passed to the directory reader and fail
with "not a directory". The check runs with error reporting disabled, so
unexpected failures exit 1 silently. An unreadable top-level `libs/`,
`packages/` or `tools/` already fails, silently; only deeper levels are treated
as empty.

**Amendments:**

- File reads also silently drop the directories that a recursive directory
  listing returns ("reading the texts keeps only the files"). Making reads fail
  requires classifying every entry, not just top-level ones.
- Legitimately absent today: each plugin's installed
  `node_modules/@opencode/plugin/package.json` before `pnpm install`. List any
  others the check depends on.
- The check runs its main program when loaded, so testing "an unexpected failure
  prints its cause" needs it restructured so the program can be run from a test.
- Permission-based tests don't work as root; prefer a `FileSystem` layer that
  fails selected paths.
