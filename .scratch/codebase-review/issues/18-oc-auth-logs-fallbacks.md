# 18: oc-auth logs why it fell back

**What to build:** Three of oc-auth's fallbacks leave no trace at the default
log level:

1. When unauthorized recovery fails because its request couldn't be sent, or
   because of an unexpected error in oc-auth, it returns the original 401, so
   OpenCode reports an authentication problem. The cause goes only into a debug
   record, and for a failed send, even that record leaves out the underlying
   cause.
2. oc-auth sends a request body it can't parse without tool aliases, and the
   billing validator can reject it. Only a debug record notes this.
3. When reading a Claude Code account's email fails, or its account file is
   malformed, oc-auth falls back to a label without the email, as if the file
   were missing, and logs nothing. A valid account file with no account/email
   metadata is not itself a failure.

Make each fallback visible at warning level, following the logging rules:
metadata in warnings, details in debug records. Recovery still returns the
original 401; only the reporting changes. The review found these by reading the
code.
